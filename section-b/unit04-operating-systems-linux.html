📘 2.1 OS Types, Kernel Mode, System Calls & Process Lifecycle (PCB)

  • OS Classifications:
    • Batch OS: Jobs with similar needs are grouped into batches without direct user interaction (CPU often idle during I/O).
    • Multiprogramming OS: Keeps multiple jobs in main memory simultaneously; when the running job waits for I/O, CPU switches to another job to maximize CPU utilization.
    • Multitasking (Time-Sharing) OS: Logical extension of multiprogramming using rapid time-slices (quantums) to minimize response time for interactive users.
    • Real-Time OS (RTOS): Strict deadline guarantees. Hard RTOS (missing a deadline is catastrophic: missile control, pacemaker, airbags) vs Soft RTOS (multimedia streaming, VoIP).
  • Dual-Mode Operation & System Calls: Mode bit = 0 (Kernel/Privileged/Supervisor Mode) vs Mode bit = 1 (User Mode). Privileged instructions (I/O, halting CPU, changing timer, modifying page tables) execute only in Kernel mode. User programs request OS services via System Calls (which trigger a software interrupt/trap switching mode bit 1 → 0).
  • The fork() Formula: If a program executes n consecutive fork() system calls unconditionally, total processes created = 2n, and number of new child processes = 2n - 1.
  • Schedulers Comparison: (1) Long-Term Scheduler (Job Scheduler): New → Ready; controls the Degree of Multiprogramming. (2) Short-Term Scheduler (CPU Scheduler): Ready → Running; runs most frequently (milliseconds). (3) Medium-Term Scheduler (Swapper): Performs Swapping (Ready/Blocked ↔ Suspended Ready/Blocked on disk) to reduce degree of multiprogramming and free RAM.

📘 2.2 CPU Scheduling Algorithms (FCFS, SJF, SRTF, Priority, Round Robin)

Core Scheduling Formulas (Memorize!):

  • Turnaround Time (TAT) = Completion Time (CT) - Arrival Time (AT)
  • Waiting Time (WT) = Turnaround Time (TAT) - Burst Time (BT)
  • Response Time (RT) = CPU First Allocation Time - Arrival Time (AT) (In non-preemptive scheduling, RT = WT).
AlgorithmModeKey Characteristic / Drawback (PYQ Favorite)
FCFS (First-Come First-Served)Non-PreemptiveSuffers from Convoy Effect (short jobs stuck behind one long CPU-bound job); zero starvation.
SJF / SRTF (Shortest Remaining Time First)Non-Preemptive / PreemptiveProvably Optimal: Gives Minimum Average Waiting Time. Drawback: Starvation of long jobs; burst time must be predicted.
Priority SchedulingBothSuffers from Indefinite Blocking (Starvation) of low-priority processes. Solution: Aging (gradually increasing priority of waiting processes).
Round Robin (RR)Preemptive (Time Quantum q)Best Response Time for Time-Sharing systems; no starvation. If q → ∞, RR degenerates into FCFS; if q → 0, context-switch overhead approaches 100%.

Worked Numerical Example (SRTF): Suppose P1(AT=0, BT=8), P2(AT=1, BT=4), P3(AT=2, BT=2). At t=0, P1 runs (0→ 1, rem=7). At t=1, P2(4) < P1(7), so P2 preempts (1→ 2, rem=3). At t=2, P3(2) < P2(3), so P3 runs to completion (2→ 4, CT3=4). Then P2 finishes (4→ 7, CT2=7). Finally P1 finishes (7→ 14, CT1=14). TAT = [14-0=14, 7-1=6, 4-2=2], WT = [14-8=6, 6-4=2, 2-2=0] ⇒ Avg WT = (6+2+0)/3 = 2.67 ms.

(2) Sabse kam **Average Waiting Time** kaun deta hai? **SJF / SRTF**! (3) **Starvation** ka permanent upaay kya hai? **Aging** (jaise-jaise waiting time badhe, process ki priority badha do)!

📘 2.3 Process Synchronization, Critical Section & Semaphores

  • Race Condition: Occurs when multiple concurrent processes access and manipulate shared data simultaneously and the final value depends on the exact order of execution.
  • Three Conditions for a Valid Critical Section Solution:
    1. Mutual Exclusion (Mandatory): Only one process can be inside its Critical Section (CS) at any instant.
    2. Progress (Mandatory): If no process is in CS and some wish to enter, only those not in their Remainder Section decide who enters next in finite time (no deadlock).
    3. Bounded Waiting: There is a strict upper bound on the number of times other processes are allowed to enter CS after a process has requested entry (prevents starvation).
  • Semaphores (Dijkstra): Integer synchronization variable accessed only through two atomic operations:
    • P(S) / wait(S) / down(S): Decrements S (S = S - 1; blocks if S < 0).
    • V(S) / signal(S) / up(S): Increments S (S = S + 1; wakes up a blocked process).
  • Counting Semaphore Numerical Formula: If a counting semaphore is initialized to S0, and p wait(P) operations and v signal(V) operations are performed: Final Value Sfinal = S0 - p + v. If Sfinal < 0,then |Sfinal| is the exact number of processes currently blocked in the suspended queue!

📘 2.4 Deadlocks: Coffman's 4 Conditions, Prevention & Banker's Algorithm

Four Necessary Conditions for Deadlock (Coffman Conditions — All 4 must hold simultaneously):

  1. Mutual Exclusion: At least one resource is held in a non-sharable mode.
  2. Hold and Wait: A process holding at least one resource is waiting to acquire additional resources held by other processes.
  3. No Preemption: Resources cannot be forcibly taken away; they are released only voluntarily by the process holding them.
  4. Circular Wait: A closed chain of processes exists (P0 → P1 → … → P0) waiting for resources. (Prevented by imposing a strict increasing numerical ordering on resource types!).
  • Resource Allocation Graph (RAG): If every resource type has a single instance, a cycle in RAG is both necessary and sufficient for deadlock. If resource types have multiple instances, a cycle is necessary but NOT sufficient.
  • Banker's Algorithm (Dijkstra — Deadlock Avoidance): Uses matrices Max, Allocation, Available, and calculates Need[i] = Max[i] - Allocation[i]. A state is Safe if there exists at least one Safe Sequence where Need[i] ≤ Work (Available). Note: An Unsafe State does NOT automatically mean Deadlock—it means deadlock *may* occur if processes request their maximum claims.
  • Deadlock-Free Minimum Resources Formula (Super High-Yield!): If there are P processes and each process needs maximum Mi units of an identical resource, the minimum resources R required to guarantee ZERO deadlock is:
    Rmin = ∑i=1P (Mi - 1) + 1 = P(M - 1) + 1

Sabhi ko (3-1)=2 de do (4 × 2 = 8), aur bas **1 extra** rakh do (8 + 1 = 9 drives) — zindagi mein kabhi Deadlock nahi lagega!

📘 2.5 Memory Management, Paging, Virtual Memory, Page Replacement & Disk Scheduling

  • Contiguous Allocation Strategies: First Fit (first hole big enough — fastest), Best Fit (smallest hole big enough — leaves tiny unusable external fragments), Worst Fit (largest hole).
  • Internal vs External Fragmentation:
    • Internal Fragmentation: Wasted space inside an allocated fixed-size partition or page frame. Occurs in Fixed Partitioning and Paging (on average 0.5 page per process).
    • External Fragmentation: Total free memory is sufficient for a request, but it is not contiguous (scattered in small holes). Occurs in Variable Partitioning and Pure Segmentation. Solved by Compaction or Paging.
  • Paging & TLB Formula: Logical address split into Page Number (p) and Page Offset (d). Physical address split into Frame Number (f) and Offset (d). Notice that Offset size d never changes because Page Size = Frame Size = 2d. With a Translation Lookaside Buffer (TLB, associative high-speed cache) having hit ratio α, TLB access time Ttlb, and memory access time Tm:
    EMAT = α(Ttlb + Tm) + (1 - α)(Ttlb + 2Tm)
  • Virtual Memory & Page Replacement Algorithms:
    • FIFO (First-In First-Out): Replaces the oldest page in memory. Suffers from Belady's Anomaly (increasing the number of page frames can paradoxically increase page faults, e.g., reference string 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 with 3 frames gives 9 faults, with 4 frames gives 10 faults!).
    • Optimal (OPT / Belady's Min): Replaces the page that will not be used for the longest period in the future. Gives lowest page faults; used as benchmark; free from Belady's anomaly.
    • LRU (Least Recently Used): Replaces the page that has not been used for the longest time in the past. Stack-based algorithm ⇒ Never suffers from Belady's Anomaly.
    • Thrashing: When a process spends more time paging (swapping pages in and out) than executing instructions because its total working set exceeds available physical frames. Solved using the Working-Set Model or Page-Fault Frequency (PFF) control.
  • Disk Scheduling Algorithms: (1) FCFS (Fair, high head movement), (2) SSTF (Shortest Seek Time First — greedy, can cause starvation of distant cylinders), (3) SCAN (Elevator Algorithm) (Moves to end of disk 0 or Max cylinder, then reverses), (4) C-SCAN (Circular SCAN) (Services requests in one direction only, jumps back to start for uniform wait time), (5) LOOK / C-LOOK (Reverses at the last request rather than going all the way to the physical disk end).
💡 Desi / Hinglish Concept Intuition: Paging mein **External Fragmentation ZERO** hoti hai! **Belady's Anomaly** sirf **FIFO** mein hoti hai (LRU aur Optimal Stack algorithms hain, unमें kabhi nahi hoti). Aur **SCAN** algorithm ko hi **Elevator Algorithm** kehte hain!

📘 4.6 Complete Linux & Open-Source OS Module: Directory Structure, File Permissions (chmod) & Essential Shell Commands

1. Linux Architecture, Booting Sequence & File System Hierarchy (FHS):

  • Linux Architecture (4 Concentric Layers): Hardware (CPU, RAM, Disks) → Linux Kernel (Monolithic modular kernel created by Linus Torvalds in 1991; manages processes, memory, device drivers, system calls) → Shell (Command-line interpreter bridging user & kernel: bash Bourne-Again Shell, sh, zsh, csh) → User Applications & Utilities.
  • Booting Sequence: Power On → BIOS/UEFI runs POST (Power-On Self-Test) → Reads MBR/GPT → Starts Bootloader (GRUB Grand Unified Bootloader) → Loads Linux Kernel (`vmlinuz`) into RAM → Starts first process systemd / init (PID = 1!).
  • Standard Linux Directory Hierarchy (Root /):
    • / (Root): Top of the entire single-rooted inverted tree hierarchy.
    • /bin & /sbin: Essential user binaries (ls, cp, mv, cat) and system administrator binaries (fdisk, reboot, iptables).
    • /etc: All System Configuration files (e.g., /etc/passwd user accounts, /etc/shadow encrypted passwords, /etc/fstab).
    • /home vs /root: /home/username is for regular users (shorthand ~); /root is the home directory of the superuser (root, UID = 0).
    • /dev: Device files (everything in Linux is a file! e.g., /dev/sda, /dev/null black hole).
    • /proc: Virtual in-memory filesystem holding live process & kernel information (/proc/cpuinfo, /proc/meminfo).
    • /var & /tmp: Variable data (logs /var/log, mail/print spools) and temporary files cleared on reboot.

2. Linux File Permissions (Octal rwx = 421), chmod, umask & Inodes:

  • 10-Character Permission String (e.g., -rwxr-xr--):
    • 1st char (File Type): - (Regular file), d (Directory), l (Symbolic link), b (Block device), c (Character device).
    • Next 9 chars (3 groups of 3): User/Owner (u) | Group (g) | Others (o).
    • Octal Weights: Read (r) = 4, Write (w) = 2, Execute (x) = 1, No permission (-) = 0.
    • Examples: chmod 755 file.sh → 7 (4+2+1 = rwx) for Owner, 5 (4+0+1 = r-x) for Group, 5 (r-x) for Others → -rwxr-xr-x! chmod 644 doc.txt → -rw-r--r--. Symbolic: chmod u+x,g-w,o=r file.
    • Default umask Calculation: Base permissions are 666 for new files (no execute by default) and 777 for new directories. With standard umask 022: New File = 666 − 022 = 644 (rw-r--r--); New Directory = 777 − 022 = 755 (rwxr-xr-x)!
